Staged refactor to make the external structure simpler: **cube = geometry, solver = search**. Each stage is behavior-preserving ("move, not change"); acceptance test = the 2^4 batch gives **identical numbers** before/after (RNG order is the main risk).

**STAGE 1 -- DONE & verified 2026-08-07.** Extracted `TRubikSolver` (new file) from `TRubikCube`. Solver holds the GA loop + per-solve state (`Score, ScoreLadder, Scrambled, Best, IterationsCount, Stall, ComputeTime`, `GetNextMoves`, `NextCluster`) and a `Cube` handle. Created **fresh right before each solve** (construction IS the reset; ctor does the old `Reset`'s only job, `ActiveCubie=null`) -- Form1 `button1_Click` makes it, batch makes one per run; the cube-rebuild sites (Load / Size / N change) never mention it. `TRubikCube.Reset()` deleted. Cube gained two helpers the solver's `NextCluster` calls: `InvalidateActiveCluster()` (=`activeCluster=null`, unconditional) and `ActivateCluster()` (`RebuildClusterMoves+ComputeSolvedInSlices+GetSolveSeq` -- the discarded `GetSolveSeq` STAYS, it advances `TChromosome.Rnd`). `Gpu.ExecuteGA(TRubikSolver solver)` now reads `solver.Cube/Score` and writes `solver.IterationsCount` (were `cube.*`). **`Gpu.ScoreCube(TRubikCube)` stays cube-only** -- Form1 calls it on a throwaway `new TRubikCube(RubikCube)` with no solver. `TRubikGenome.RubikCube = Cube` still assigned before ExecuteGA (FreeMoves/buffer path needs it).

**STAGE 2 -- DONE 2026-08-07.** `Coherent` -> solver instance field (per-solve latch), threaded into every GPU entry point as a param (`CreateBuffers/ScoreCube/EvalZeroSpecimen/SeedStats/SeedFast` all take `coherent`; `ExecuteGA` reads `solver.Coherent`). `Floor` -> `TRubikSolver.Floor` STATIC config (never mutated; a search knob, not GPU state -- a public static is read by class name from Gpu/Form1, so "the report reads it" was never a reason to keep it in Gpu). `ExecuteGA(solver, out int gens)` returns gens; solver does `IterationsCount += gens` (no more side-channel write). RNG preserved: passing solver.Coherent reproduces the old static's value at each call site (matters because SeedFast(coherent) changes BuildSeedMoves' RNG draws).

**STAGE 3 -- DONE & verified 2026-08-07 (builds; 2^4 batch numbers IDENTICAL; user felt it "runs a bit better" = incidental, lighter cube copies / Clusters built once, search unchanged).** "search state leaves the cube", done as ONE big piece. KEY FINDING: `ActiveCubie` + `GetClusterMoves`/`ClusterMoves` wear TWO hats -- solver TARGET *and* a geometry SCRATCH used by shuffle (Form1 button2 + batch), the saveClusters/verifyClusters menus, and TGreedyDiversity (`cube.ActiveCubie = x; cube.GetClusterMoves()`), plus a DEAD CPU-GA path in TRubikGenome (MutateGene->ClusterMoves, Genesis->GetSolveSeq, predict->ActiveCluster). So it's a DISENTANGLE, not a move. Decomposition: (1) `GetClusterMoves(TCubie cubie)` becomes a geometry fn TAKING a cubie, stays on cube; shuffle/menus/greedy pass an explicit cubie. (2) `TCluster` gains `List<TCubie> Cubies`; `TRubikCube.Clusters` becomes INSTANCE (was static -- needed so cubie refs are per-cube); `MaxClusterSize` stays static; cube COPY ctor mirrors Clusters by StartIndex and NO LONGER copies target state. (3) Solver gets the TARGET: `ActiveCubie`, `ActiveCluster` (a `TCluster` REFERENCE, = `Cube.Clusters[ActiveCubie.ClusterIndex-1]`; usages go `.Cubies`), `SolvedCubies`, `SolvedInSlices`, cached `ClusterMoves`, + ALL seed machinery (`BuildSeedMoves`, `GetSolveSeq*`, `RotCountMode*`, `RandomOrder`, `CorrectSeq`, `GetOrder`, DFS...). (4) GPU public surface SINGLE-PARAM: `ScoreCube(solver)`, `ExecuteGA(solver, out gens)`; internally `CreateBuffers/EvalZeroSpecimen(solver)`. noOpPenalty scores a throwaway `new TRubikSolver(new TRubikCube())` (ActiveCubie null -> empty target, no seeds). (5) DEAD CPU path in TRubikGenome (Genesis/MutateGene/predict): user says COMMENT OUT (not delete -- wants it as reference; uneasy that seeds "stopped working"). TGA<TRubikGenome> is only static config (no `new TGA` anywhere), so the CPU evolve loop is confirmed dead. RNG UNCHANGED (faithful move, same draws/order) -> batch 2^4 must still match; re-baseline ONLY if we later change draws (e.g. remove the vestigial seed-build in the ScoreCube path -- deferred).

**STAGE 3:** trajectory as a **log** on the solver (StringBuilder/List<string> + a `TrackTrajectory` toggle), recorded in `GetNextMoves`. NOT file-coupled -- the caller (Form1 interactive OR batch) decides whether/where to persist. Unifies interactive + batch (both drive the solver) and lets interactive Solve overwrite one trajectory file. Today only the batch's `SolveOnceHeadless` builds the traj by hand.

**STAGE 4 (mostly independent):** `TCluster` (already has `Size`) gains `List<TCubie> Cubies` -- **TCubie references, not int indices** (indices are meaningless; TCubie carries `StartIndex`, and the debugger shows real objects: StartIndex/State/position on the active cluster). NO static membership map: the scratch ctor computes membership once (orbit detection), the **copy ctor mirrors** src clusters by the same `StartIndex` into the copy's `Cubies` (already done for the active cluster -- generalize to all). `ActiveCluster` becomes a reference to one `Clusters[]` element. Move cluster-geometry ops (`validSlices`, `GetClusterMoves`, GPU-buffer build via `Cubies.Select(c=>c.StartIndex)`) into `TCluster`; solve-progression (which active/done, `NextCluster`) stays in the solver. `Turn` stays on the cube (geometry action). Copy gotcha: a copy must REBUILD its cluster->cubie refs (can't share src's TCluster objects).

Constraint the user set: don't pile on mechanisms -- refactor to firm the foundation, not build a house of cards. See [[build-workflow]] (user builds in VS; just save edits).
